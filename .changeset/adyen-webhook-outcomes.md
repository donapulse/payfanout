Adyen webhook events now map the outcomes Adyen documents: a refused capture request arrives as `unknown` instead of `payment.failed`, `TECHNICAL_CANCEL` maps like `CANCELLATION`, and the dispute closures `ISSUER_RESPONSE_TIMEFRAME_EXPIRED`, `PREARBITRATION_WON` and `SCHEME_ARBITRATION_WON` arrive as `payment.chargeback_won` and `PREARBITRATION_LOST`, `SCHEME_ARBITRATION_LOST` and `DISPUTE_DEFENSE_PERIOD_ENDED` as `payment.chargeback_lost`, so a later loss can override the provisional win of `CHARGEBACK_REVERSED`. `event.pspPaymentId` now comes only from a field Adyen documents as the payment's reference: `originalReference`, or the event's own `pspReference` on `AUTHORISATION`, `EXPIRE` and `OFFER_CLOSED`, so a report notification or a dispute event without `originalReference` carries none. Verification checks every signed value against the type Adyen's webhook schema gives it, refusing a delivery whose values were re-typed, and follows Adyen's unescaped join: a `:` or `\` in `merchantReference` now verifies, and a `:` is refused only in the other signed values. Keep the Standard webhook on the JSON method, select `OFFER_CLOSED`, enable "Include the originalReference for CHARGEBACK_REVERSED events", and upsert events by `event.id`, keeping the latest delivery.
