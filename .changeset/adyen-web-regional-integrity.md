Load Adyen Web 6.45.2 instead of 6.41.0, with the Subresource Integrity hashes Adyen publishes for its script and stylesheet so the browser refuses a modified file, from the CDN host of the account's region: set `adyenEnvironment` to `live-us`, `live-au`, `live-nea` or `live-in` for a live account served from there (every live account loaded from the European host before). Setting `sdkVersion` loads both files without the integrity check, and `sdkUrl` or `stylesheetUrl` the file it replaces; a `<script>` your page adds itself for the default URL needs the same `integrity` and a `crossorigin` attribute, or loading fails with `invalid_request` while `window.AdyenWeb` is not defined yet. The constructor now throws `invalid_request` for a client key whose `test_`/`live_` prefix contradicts `environment`, for an `adyenEnvironment` Adyen does not document (such as `live-apse`) and for one that contradicts `environment`. A script that fails to load, or loads without defining `window.AdyenWeb`, is loaded again on the next mount along with a stylesheet that failed, and Adyen Web errors are classified by name, so a network or script failure is a retryable `psp_unavailable` and an implementation error `invalid_request` (still `authentication_required` during a 3-D Secure challenge).
