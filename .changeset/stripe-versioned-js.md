Load Stripe.js in the build of the API version you pin, instead of always loading `https://js.stripe.com/v3`, whose requests followed the account's default version. A version with a release name, such as `2026-08-26.dahlia`, loads that release's build (`https://js.stripe.com/dahlia/stripe.js`; acacia, basil, clover and dahlia are known), which speaks the API version Stripe pins it to within that release, not necessarily yours. A date alone, such as `2024-06-20`, still loads v3, now given that version, so the browser speaks exactly it. A Stripe.js the page already runs is still used, now by build: v3 is given your version, a release's included, and another release's build is used as it is, with a console warning in a sandbox. A `<script>` your page added for the build that has not loaded yet is now waited for, up to 30 seconds, instead of failing the mount. The new `hideTestingAssistant` option hides the testing assistant Stripe.js shows in a sandbox from the clover build on.

Breaking: `apiVersion` is required. Pass the server adapter's `apiVersion`, or, while the server is on a release this adapter does not know yet, a version of the newest release it knows. A missing or malformed version, a date alone from 2024-09-30 on, a release the adapter knows no build for, a preview version and a version carrying beta headers are refused with `invalid_request`. The `sdkUrl` option is removed and refused, as Stripe.js must load from `https://js.stripe.com` and the version picks the file. If your Content-Security-Policy names Stripe.js by path, list the host `https://js.stripe.com` instead, since the versioned builds take their frames and chunks from `https://js.stripe.com/v3/`.

Moving from v3 to a release's build changes what Stripe.js does, as each release's changelog lists: from basil, the Payment Element's default layout is an accordion instead of tabs (give `<PaymentFields>` `fieldOptions={{ layout: "tabs" }}` to keep tabs); from clover, it no longer collects a postal code for card payments in Canada, the United Kingdom and Puerto Rico, Elements refuses the client secret of an intent that is already succeeded, canceled, processing or awaiting capture (reported to `onError`), and a sandbox shows Stripe's testing assistant; from dahlia, a boolean `layout.radios` in `fieldOptions` throws.
